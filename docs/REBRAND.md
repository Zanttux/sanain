# Rebrand: Sanain → Text³ (migration report)

Owner decision D27 (2026-11-27). Source: the owner's Text³ handoff package
(START_HERE, BRAND, MIGRATION, PACKAGING, website prototype, tokens,
raster drafts); `assets/brand/approved-reference.png` is the visual
authority. Branch `rebrand/text3`, based on main at 5b0487a (0.2.1). No
version reset: the next release continues the 0.2.x/0.3 sequence.

The owner approved the repository rename to **Zanttux/text3** on
2026-11-27. The rename itself, and anything else that changes an external
identity, is done by the owner session at cutover (below); this branch
only prepares for it.

## Commits
1. **Add the Text³ brand assets** — handoff artwork in `assets/brand`
   (reference unchanged, drafts unchanged under `drafts/`), traced SVG
   masters, `scripts/brand-trace.py`, `scripts/make-icons.py` (replaces
   `make-icons.sh`) and every derived raster.
2. **Rename the workspace crates** — `sanain-*` → `text3-*`, mechanical
   (git detects the moves as renames), lockfile regenerated by Cargo.
3. **Rename the product to Text³** — visible strings, 26 locales,
   binary `text3`, packaging names, desktop id, registry keys, URLs.
4. **Move user data to text3 folders and keep Sanain compatibility** —
   first-start copy, `SANAIN_*` aliases, legacy registration cleanup,
   installer upgrade cleanup.
5. **Copy Sanain folders only when the editor starts** — fix found while
   testing the release build (`--help` ran the first-start copy).
6. **Text³ installer artwork, DMG layout and website** — Inno Setup
   wizard images, DMG background and window layout, deb rename transition
   and `sanain` command alias, website and Pages, this report and D27.

Rollback: `git revert` the six commits in reverse order (or drop the
branch before merge). After merge and a release, users who already ran
Text³ keep their Sanain folders untouched, so going back to a Sanain build
loses nothing written before the switch; settings changed in Text³ after
the switch stay in the `text3` folders (same file formats, so they can be
copied back by hand). Rolling back the repository rename is a separate
owner decision: rename back, re-check Pages, Actions and release URLs.

## Decisions
- **Names:** Text³ in UI, docs, installer, bundle display name and file
  name (`Text³.app`; U+00B3 has no Unicode decomposition, so no NFC/NFD
  issues); `text3` for the binary, crates, paths, package ids, release
  files, Windows install folder `Programs\Text3` for new installs.
- **Crates renamed** (`text3-app`, `text3-core`, …): MIGRATION.md asks for
  package names to follow; done as one mechanical commit so the review of
  real changes is not drowned.
- **Linux desktop id** `io.github.zanttux.text3` (matches the new
  repository); window `app_id`/`StartupWMClass` `text3`.
- **macOS bundle id kept** (`io.github.zanttux.sanain`): changing it would
  lose Launch Services registrations and privacy (TCC) grants, and an
  upgraded bundle under a new id was not tested. Changing it later needs
  its own migration test. Because the bundle file name changes
  (Sanain.app → Text³.app), dragging the new app to Applications leaves
  Sanain.app beside it; users may delete it (their data is copied).
- **Inno Setup AppId kept** (`{6E7B1D2C-58A4-4B5E-9C1F-5A1A9E0D3B21}`): the
  Text³ installer upgrades a Sanain installation in place (Inno reuses
  the previous folder), deletes `sanain.exe` and the old shortcuts and
  registry keys; fresh installs go to `Programs\Text3`.
- **Data folders** move to `text3`, with a copy-on-first-start (below)
  instead of keeping the old names forever.
- **No slogans:** "The power of words", "AI-built. Human-led.
  Community-driven." and "Fast by design…" removed from README, About,
  locales and website. AI involvement is still disclosed plainly.
- **Website** follows the handoff: white/#F4F4F4 surfaces, #D4D4D4 borders,
  ink text, green accent only (links #344B23 for AA contrast), lockup on
  white, system fonts, English only, real release links, canonical and
  OpenGraph URLs for https://zanttux.github.io/text3/ (Pages does not
  redirect from /Sanain/).

| Inno Setup AppId | GUID above | unchanged | in-place upgrade |
| File formats | `sanain-settings 1` etc. | unchanged | both apps read each other's files |

First-start copy (`text3_app::migrate`): for each old/new pair, if the old
folder exists and the new one has no `migrated-from-sanain` marker, copy
every regular file the new folder does not already have (never
overwriting), recreate folders with their permissions (recovery stays
owner-only), skip symbolic links, copy through a temporary name so an
interrupted copy never leaves a truncated file, then write the marker
(with counts). The old folder is only read and stays as the backup; Sanain
keeps working with it. Copied files are logged on stderr and announced
once in the status bar ("Settings and data from Sanain were copied to
Text³…", all 26 locales). Errors are logged and retried next start.
Folders chosen by variables or portable mode are not touched.

Automated tests (`migrate.rs`, `settings.rs`, `shellreg.rs`, `update.rs`):
fresh install (nothing created), upgrade (all files copied, byte-equal,
old folder unchanged, marker written, no temp files), repeated start (no
second copy, later changes on either side untouched, nothing announced),
both present (new files never overwritten, counts recorded), same folder,
owner-only permissions kept and symlinks not followed (Unix), `TEXT3_`
over `SANAIN_` lookup order, legacy portable marker, legacy desktop entry
removal on register/unregister, legacy Windows key deletion in both
command lists, release pages under both repository names.

Not tested: Windows installer upgrade from a real Sanain install, Windows
registry cleanup on a real machine (the CI round-trip test covers the new
keys), Linux deb upgrade from the `sanain` package, uninstall on Windows
and Linux, macOS drag-install over an existing Sanain.app.

## Artwork and icons
- `approved-reference.png` copied byte-identical (SHA-256
  `905c37d205501f96fbc2759de4ebe07d3fd4f80e1e0ce2c174149efc84c500f6`);
  all handoff rasters kept unchanged in `assets/brand/drafts/`.
- **Vector masters:** `text3-lockup.svg`, `text3-mascot.svg`,
  `text3-document.svg` are flat-fill traces of the reference made with
  vtracer (MIT, run locally) after keying out the page background (the
  tail-tip curl kept opaque, the "e" counter cleared), dropping the swoosh
  for the mascot master and snapping all fills to the artwork's eight
  sampled colours (shading flattened). No raster is embedded. Compared at
  1:1 and 2× with the reference: pose, silhouette, expression, spots,
  tufts and wordmark match; a few contours are slightly softer than a
  hand-drawn master, and the eye highlights are simplified. They are good
  enough to generate every shipped raster, but they are **automatic
  traces, not a designer's hand-drawn master**: TODO for a designer to
  redraw/clean the paths (node count, curve continuity) before they are
  called final. Derived: `text3-lockup-plate.svg` (white plate, dark
  surfaces), `text3-lockup-mono.svg` (one colour).
- **Small icons:** the scaled full mascot is unreadable at 16–32 px (see
  the draft `drafts/icons/app-16.png`), and its dark outline vanishes on
  dark taskbars. 16 and 24 px show the face only, 32 px the head with
  tufts, each with a 1 px white outline; 48 px and up show the whole
  mascot. The macOS icon puts the mascot on a white rounded plate on
  Apple's grid (face/head crop at 16/32 px). Inspected at 1:1 and 8× on
  white and #1E1E1E backgrounds. Removed the residual green swoosh
  fragment under the draft icon.
- **Platform files:** `packaging/icons/text3-{16…1024}.png`, `text3.ico`
  (16–256), `text3.icns`, `text3-document-*.png`, `text3-document.icns`
  (macOS document type icon); Inno Setup `wizard-image-{100,200}.bmp`
  (164×314, 328×604, mascot on white) and `wizard-small-{100,200}.bmp`
  (55×58, 110×116); `packaging/macos/dmg-background.tiff` (660×420 + 2×,

   Website workflow; /Sanain/ will 404, Pages does not redirect); Actions
